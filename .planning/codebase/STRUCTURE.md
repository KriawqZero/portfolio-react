## Directory Purposes

**`src/`:**
- Purpose: React frontend source code
- Contains: Components, hooks, styles, content data
- Key files: `App.tsx` (orchestrator), `main.tsx` (React entry), `data/content.ts` (copy source)

**`api/`:**
- Purpose: Vercel serverless functions
- Contains: `ask.ts` — POST handler for AI chat
- Deployment: Automatic via Vercel (detects `api/` directory)

**`lib/ai/`:**
- Purpose: Reusable validation, configuration, and AI support logic
- Contains: Types, validation, rate limiting, caching, document retrieval
- Strategy: Shared between API handler and build scripts; no component-specific logic

**`knowledge/`:**
- Purpose: AI knowledge base source files
- Contains: `approved/` (hand-written), `policies/` (system constraints)
- Workflow: Editor creates `.md` files with frontmatter, `scripts/knowledge/build-index.ts` compiles into `lib/ai/generated/knowledge-index.ts` at build time

**`scripts/`:**
- Purpose: Build-time and utility scripts
- Contains: CV generation, image optimization, knowledge indexing, AI testing
- Execution: Triggered by npm scripts (`pnpm cv:gen`, `pnpm knowledge:build`, etc.)

**`public/`:**
- Purpose: Static assets served directly
- Contains: Case study images, project media, generated images
- Notes: Not bundled; served as-is by Vercel

**`docs/`:**
- Purpose: Development and process documentation
- Contains: GSD plans, specifications, design decisions
- Notes: For developer reference; not part of shipping code

## Key File Locations

**Entry Points:**

- **Browser:** `src/main.tsx` (creates React root, mounts `LanguageProvider`, renders `App`)
- **App:** `src/App.tsx` (orchestrates section composition, GSAP context, ScrollTrigger)
- **API:** `api/ask.ts` (POST `/api/ask` handler for AI requests)

**Configuration:**

- **Build:** `vite.config.ts` (Vite setup, apiDev middleware)
- **TypeScript:** `tsconfig.json`, `tsconfig.app.json`, `tsconfig.api.json`
- **Linting:** `eslint.config.js` (flat config)
- **Project:** `package.json` (dependencies, scripts)
- **Env:** `.env` file (never committed; contains secrets — see CLAUDE.md)

**Core Logic:**

- **Content:** `src/data/content.ts` (single source of truth for all copy)
- **Language Context:** `src/hooks/useLanguage.tsx` (language + platform detection)
- **Smooth Scroll:** `src/hooks/useSmoothScroll.ts` (Lenis + GSAP ticker integration)
- **AI Configuration:** `lib/ai/config.ts` (environment variable parsing)
- **Request Validation:** `lib/ai/validate-request.ts` (schema + size checks)
- **Response Validation:** `lib/ai/validate-answer.ts` (JSON schema + fact-checking)
- **Rate Limiting:** `lib/ai/limits.ts` (Redis counters, sliding window, daily limits)
- **Document Retrieval:** `lib/ai/retrieval.ts` (scoring algorithm, document selection)
- **Prompt Building:** `lib/ai/prompt.ts` (system prompt + document block assembly)
- **Response Caching:** `lib/ai/cache.ts` (Redis-backed, 7-day TTL)

**Testing & Diagnostics:**

- **CV Generation:** `scripts/generate-cv.ts` (entry), `scripts/templates/` (HTML templates)
- **Knowledge Building:** `scripts/knowledge/build-index.ts` (Markdown → TypeScript index)
- **Image Optimization:** `scripts/optimize-images.ts` (WebP/AVIF generation)
- **AI Testing:** `scripts/ai/*.ts` (cost measurement, security validation, conversation replay)

## Naming Conventions

**Files:**

- **React components:** `PascalCase.tsx` (e.g., `Hero.tsx`, `AiChat.tsx`)
- **Utility/library code:** `camelCase.ts` or `kebab-case.ts` (e.g., `useSmoothScroll.ts`, `validate-request.ts`)
- **Markdown knowledge:** `kebab-case.md` (e.g., `core-profile.md`, `ai-workflow.md`)
- **Scripts:** `camelCase.ts` (e.g., `generate-cv.ts`, `build-index.ts`)

**Directories:**

- **Feature/section directories:** `kebab-case` (e.g., `components/`, `scripts/knowledge/`)
- **Logical groupings:** descriptive plural (e.g., `templates/`, `policies/`, `approved/`)

**TypeScript & JavaScript:**

- **Interfaces/types:** `PascalCase` (e.g., `LanguageContextType`, `KnowledgeDoc`, `AskRequest`)
- **Enums:** `SCREAMING_SNAKE_CASE` for constants (e.g., `STOPWORDS`, `FIXOS`)
- **Functions:** `camelCase` (e.g., `tokenizar()`, `pontuar()`, `selecionarDocumentos()`)
- **React hooks:** `useXxx` (e.g., `useLanguage()`, `useSmoothScroll()`)
- **Constants:** `SCREAMING_SNAKE_CASE` (e.g., `MAX_HISTORICO`, `CHAVE_SESSAO`)
- **Domain names:** Portuguese where natural (e.g., `conteudo`, `trajetoria`, `resposta` — used in component IDs)

## Where to Add New Code

**New Section/Page Component:**
- Location: `src/components/[SectionName].tsx`
- Steps:
  1. Add section fields to `src/data/content.ts` (both `ptContent` and `enContent`)
  2. Create `src/components/[SectionName].tsx` component; import and use `useLanguage()` to read `t.[section]`
  3. Add GSAP/ScrollTrigger animations if scroll-triggered (wrap in `gsap.context()`, call `ctx.revert()` on unmount)
  4. Add to `App.tsx` composition in narrative order
  5. Add responsive behavior with `gsap.matchMedia()` if mobile needs differ from desktop

**New Utility Hook:**
- Location: `src/hooks/use[Name].ts` or `use[Name].tsx`
- Pattern:
  ```typescript
  export function use[Name]() {
    // Hook logic here
  }
  ```
- Use in components via `const result = use[Name]()`

**New Content (Non-Component):**
- Location: `src/data/content.ts` only
- Pattern:
  ```typescript
  export const ptContent = {
    // ... existing sections
    newSection: {
      field1: 'value pt',
      // parallel en field in enContent
    }
  }
  ```
- Reference in components: `const { t } = useLanguage(); t.newSection.field1`

**New AI Knowledge Document:**
- Location: `knowledge/approved/[name].md`
- Format:
  ```markdown
  ---
  id: unique-doc-id
  type: [profile|project|practice|index]
  topics:
    - keyword1
    - keyword2
  aliases:
    - alternate name
  sourceLabel: Optional
  sourceHref: https://optional-link
  ---

  Document body in markdown.
  ```
- After saving:
  1. Run `pnpm knowledge:build`
  2. New document appears in `lib/ai/generated/knowledge-index.ts`

**New API Endpoint:**
- Approach: Add new handler file `api/[route].ts`
- Convention: Match Vercel's function routing (path → file)
- Example: `api/some/path.ts` handles `POST /api/some/path`

**New Build Script:**
- Location: `scripts/[name].ts`
- Execution: Add to `package.json` scripts section, e.g., `"custom:cmd": "tsx scripts/name.ts"`
- Run via: `pnpm custom:cmd`

**New CSS Styling:**
- Strategy: No component-level `.css` imports; all styling in `src/index.css` or inline `style={}` objects
- No Tailwind, no CSS-in-JS libraries; custom CSS only
- Avoid new colors unless absolutely necessary (use `#6D4AFF` accent or neutral grays)

**New Frontend Tests:**
- Not applicable: No test framework set up
- Alternatives: Use `scripts/ai/teste-*.ts` for manual integration testing

**New CV Variant:**
- Location: `scripts/cv.[variant].content.ts` (data), `scripts/templates/[variant].ts` (HTML rendering)
- Entry point: `scripts/generate-cv.ts` (add to `Variante` type and `VARIANTES` array)
- Run: `pnpm cv:gen [variant]` to generate PDF

- Purpose: Build output (auto-generated)

## Build Pipeline

**Development:**
```bash
pnpm dev
```
- Starts Vite dev server with hot reload
- Mounts `api/ask` handler locally via middleware (no actual Vercel function)
- Can call `/api/ask` from browser just like production

**Production Build:**
```bash
pnpm build
```
1. Runs `pnpm knowledge:build` (pre-hook)
   - Compiles `knowledge/approved/` + `src/data/content.ts` into `lib/ai/generated/knowledge-index.ts`
2. Runs TypeScript compiler: `tsc -b` (checks all tsconfig.json files)
3. Runs Vite build: `vite build`
   - Bundles `src/` → `dist/`
   - Vercel detects `api/ask.ts` and deploys as function
   - Static files in `public/` are copied to `dist/`

**Deployment:**
- Vercel detects commits to main branch
- Runs `pnpm build` and deploys
- `api/ask.ts` deployed as serverless function at `https://marciliortiz.dev.br/api/ask`

**Scripts:**
```bash
pnpm cv:gen [variant]     # Generate PDF (puppeteer + headless browser)
pnpm knowledge:build      # Rebuild AI knowledge index
pnpm lint                 # Run ESLint
pnpm img:gen              # Optimize images to WebP/AVIF
pnpm ai:stats             # Check current AI spending (Redis)
pnpm ai:ask               # Test AI endpoint interactively
```
